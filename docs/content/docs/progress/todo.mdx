## 前端体验与一致性优化

### 目标与验收基线

- 让用户在“选模板 → 填写内容 → 确认费用 → 生成 → 保存或继续加工”的过程中减少等待、重复填写和页面跳转造成的中断。
- 主站与创作中心统一导航名称、主题语义、表单密度、状态反馈和操作文案；独立部署边界可以保留，不以更换组件库作为前置条件。
- 分别采集移动端和桌面端第 75 百分位体验数据，目标为 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1；另行记录“进入工作台到可输入”和“点击生成到任务被服务端接受”的耗时。
- 每个阶段须通过 TypeScript、Lint、生产构建及相关行为测试；涉及布局和交互时，补充 390、768、1440、1920 宽度的视觉、键盘和可访问性验证。

### P2：性能、可观测性与长期门禁

- [x] 主站 CodeMirror 运行时改为首次显示源码/编辑消息时动态加载，并在对应入口悬停或聚焦时预加载；画布插件管理器、素材选择器和五类图片工具弹窗拆为三个按需分包，保留 Agent 既有延迟加载与预加载。主站初始入口保持 3,757.5 kB（gzip 1,083.0 kB）不变；创作中心初始入口由 1,089.00/357.52 kB 变为 1,089.18/357.63 kB，画布项目路由由 300.80/90.76 kB 降至 238.84/72.68 kB（均为 raw/gzip）。
- [x] 已在独立 Chromium 中对 96 条素材、连续加载 200 条生成历史和 1,000 条 Agent 消息各重复测量 3 次；实时 DOM 分别为 6,190、3,240、4,877 个节点，两帧交互延迟中位数分别为 9.0、28.9、19.6 毫秒，均低于 200 毫秒目标。素材与历史继续沿用分页/按需加载，Agent 保留既有 `content-visibility`；当前未观察到需要引入虚拟列表的持续渲染瓶颈。
- [x] 创作中心已通过延迟分包接入 LCP、INP、CLS，并采集“进入工作台到可输入”和“触发生成到首个任务被服务端接受”；所有事件只包含指标名、数值、归一化页面、移动端/桌面端、版本和 Web Vitals 评级。GA4/百度配置为空时不外发，查询参数、提示词、素材地址、账号标识和 Token 均不进入载荷，既有页面浏览也已去除 search/hash。
